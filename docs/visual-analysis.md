# 大数据岗位招聘信息可视化分析

**基于 3,498 条清洗后招聘岗位的 EDA 可视化 · 面向专科应届生的求职决策支持**

技术栈：Python（Pandas / NumPy / Matplotlib）· 数据清洗 → 分组聚合 → 四维可视化 → 业务解读

> 本文所有数字均由 `cleaned_jobs.csv`（清洗后 3,498 行 × 19 字段）全量实算得出，绘图脚本 `src/job_visualization.py` 可一键复现。
> 数据来源：和鲸社区公开招聘数据集（原始 4,100 条 × 15 字段，全国范围「大数据开发」主题岗位，快照时间 2022-11）。

---

## 一、可视化方案总览

先定问题，再定图。四张图分别回答一个求职决策问题，不做「为了好看而画」的图。

| 图号 | 图表类型 | X 轴 | Y 轴 | 回答的业务问题 |
|---|---|---|---|---|
| 图 1 | 柱状图（含柱顶/柱内双标注） | 学历要求（本科 / 大专 / 硕士 / 博士 / 中技 / 高中 / 初中） | 岗位数量（条） | **专科能不能投？** 学历门槛的真实高度 |
| 图 2 | 横向条形图（重点城市高亮） | 岗位数量（条） | 城市（Top12，按数量降序） | **去哪里投？** 目标城市的岗位供给量级 |
| 图 3 | 横向条形图（按需求强度渐变着色） | 提及该技能的职位描述数（条） | 技能关键词（Top15） | **补什么技能？** 技能需求的优先级排序 |
| 图 4 | 堆叠柱状图（按学历分档堆叠） | 工作经验要求（无需经验 → 8 年以上） | 岗位数量（条） | **应届生有多少机会？** 经验门槛的结构与专科学历的分布 |

**两处刻意的设计取舍**（面试时值得讲）：

1. **图 1 没有做「柱 + 右轴折线」的双轴图。** 本数据薪酬为区间报价（如「15-20万/年」），换算成月薪后离散化严重，各学历中位数只差 500–1,000 元。若用截断的右轴去画，视觉上会把 4% 的差异放大成数倍的「学历溢价」，属于典型图表误导。因此 Y 轴只承载岗位数，薪资中位数以柱内文字标注呈现。
2. **图 1 只对样本量 ≥100 的学历标注薪资。** 博士仅 35 条、中技 27 条、高中 23 条、初中 3 条，这些组的中位数不具备统计意义，标出来只会干扰阅读，属于「用噪声冒充结论」。

## 二、四张图表与解读

### 图 1　各学历要求岗位数量与薪资中位数

![各学历岗位数量与薪资中位数](../assets/vis_edu.png)

**读图要点**

- 本科要求 **2,348 条（67.1%）**，大专要求 **846 条（24.2%）**，两者合计 91.3%，构成本数据集的基本盘。
- 若把「要求不高于大专」的岗位全部算作专科可投池：大专 846 + 中技/中专 27 + 高中 23 + 初中 3 = **899 条（25.7%）**；反过来说，**74.3% 的岗位明确要求本科及以上**。
- 薪资维度几乎没有分层：本科中位 **12,001 元**，大专中位 **11,501 元**，差距 500 元（约 4.2%），仅相当于一个报价档位。

**业务意义**：学历在这份数据里是「筛选门槛」而非「定价依据」。它决定简历能不能过初筛，但一旦进入面试环节，薪资的差异更多由技能栈和项目经历解释。

---

### 图 2　岗位数量 Top12 城市

![Top12 城市岗位数量](../assets/vis_city.png)

**读图要点**

- 供给高度集中：上海 599、广州 358、深圳 334、北京 199，四个一线城市拿走 **42.6%**。
- 成都 **184 条**，位列全国第 6，超过杭州（147）与南京（182 相近）；重庆 **78 条**，列第 11。
- 川渝合计 **262 条，占全国样本 7.5%**——约为上海的 44%。
- 成都与重庆的薪资中位数均为 **12,501 元**，与北京持平，高于深圳、杭州的 11,501 元。

**业务意义**：川渝不是这份数据的主力市场，但成都单城的岗位体量已进入全国第一梯队，且薪资中位数不低于一线。对以川渝为目标地域的求职者，成都是主战场，重庆是补充，需同时保留一定比例的异地/远程机会。

### 图 3　技能需求 Top15

![技能需求 Top15](../assets/vis_skill.png)

**读图要点**

- 第一梯队：**SQL 1,385 条（40%）、Java 1,376 条（39%）**，两者几乎并列，覆盖四成岗位。
- 第二梯队：**数据分析 1,005 条（29%）、Python 775 条（22%）**。
- 大数据技术栈：**Hadoop 689（20%）、Linux 657（19%）、Spark 630（18%）、Hive 512（15%）**，构成「三件套 + 操作系统」的核心组合。
- 消息与存储组件为加分项：Kafka 442（13%）、HBase 391（11%）、Flink 287（8%）。

**业务意义**：Python 并不是第一优先技能。对大数据开发方向，**SQL + Java** 的覆盖率是 Python 的近两倍；而 SQL 的学习成本远低于 Java，是投入产出比最高的单项技能。

### 图 4　经验要求分布与学历构成

![经验要求分布与学历构成](../assets/vis_exp.png)

**读图要点**

- 需求重心在 3–4 年经验段：**1,205 条（34.4%）**；加上 5–7 年（753 条）与 8 年以上（194 条），**要求 3 年以上经验的岗位占 61.5%**。
- 应届友好（无需经验 / 在校生应届生）仅 **320 条，占 9.1%**；其中大专 **102 条**、本科 147 条、其他学历 71 条。
- 大专岗位 846 条的经验分布：3–4 年 284 条、1 年 158 条、2 年 155 条、5–7 年 130 条、无需经验 100 条、8 年以上 17 条。

**业务意义**：市场对「经验」的定价权重远高于学历。应届友好岗是典型的窄门（9.1%），仅凭学历达标无法进入；而「1 年经验」段（469 条，大专 158 条）是可以通过实习与项目经历跨越的第一个台阶。

## 三、面向应届生的四条业务结论

以下结论全部来自上述图表，每条都对应一个可立即执行的动作。

### 结论 1：学历卡的是「入场券」，不是「工资条」——先解决过筛，再谈议价

大专可投池 **899 条（25.7%）**，但要求本科及以上的岗位占 **74.3%**。同时，大专与本科的薪资中位数只差 500 元（11,501 vs 12,001）。

**落地动作**：投递时不要全量海投，直接用「学历要求 ≤ 大专」做第一层筛选，把 899 条压到可管理规模；同时把简历的竞争力前移到「技能 + 项目」，因为学历已经不是薪资差异的主要解释变量。反过来，遇到明确写「本科及以上」的岗位不要浪费投递额度。

### 结论 2：成都单城进全国前六，川渝要「主攻成都、保留异地」

成都 184 条排第 6、薪资中位 12,501 元；重庆 78 条排第 11；川渝合计仅占 7.5%。

**但必须正视的硬约束**：在川渝样本中，「大专 + 无需经验」的岗位只有 **6 条**（成都 5、重庆 1）。也就是说，川渝本地几乎不存在「学历和经验双达标」的应届友好岗。

**落地动作**：把求职半径设为「成都为主 + 重庆为辅 + 异地/远程保底」三层。若坚持只投川渝，就必须把「1 年经验」段（成都大专岗位中 1 年经验段可投）作为实际起点，用实习或外包经历去够门槛，而不是死守 9.1% 的应届友好岗。

### 结论 3：技能优先级是 SQL > Java > Python，不是「先学 Python」

SQL 覆盖率 40%、Java 39%、数据分析 29%、Python 22%。大数据栈 Hadoop/Hive/Spark 分别覆盖 20%/15%/18%。

**落地动作**：按覆盖率排学习顺序——① SQL 刷到能独立写多表关联与窗口函数（覆盖 40% 岗位，成本最低）；② Python 达到 Pandas 清洗 + 可视化水平（22%）；③ Hadoop/Hive/Spark 三件套做到能跑通一个端到端离线数仓 demo（合计覆盖约 1/5 岗位，且是面试区分度最高的部分）。Java 只在明确投递「大数据开发（Java 方向）」岗位时重点补，不必作为通用底座。

### 结论 4：用「项目」把经验栏从 0 填到 1，而不是等应届友好岗

3 年以上经验要求占 61.5%，应届友好岗仅 9.1%。「1 年经验」段有 469 条（大专 158 条），是量与门槛的平衡点。

**落地动作**：把课程项目包装成「可核验的经历」——本项目本身（4,100 条原始数据 → 3,498 条清洗 → 四维可视化 → 结论落表）就是一个完整的端到端案例，可在简历中按「数据采集 / 清洗 / 分析 / 交付」四段描述，并给出具体数字与图表。这样在投「1 年经验」段岗位时，可以用项目工作量与产出替代实际工龄，把可投池从 102 条扩大到 260 条（大专经验 ≤1 年）。

## 四、绘图代码与环境说明

完整脚本：`src/job_visualization.py`（另有清洗脚本 `src/bigdata_job_clean_eda.py`）。

```python
# 中文显示必备三行，否则图中中文全部变成方块
plt.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei", "DejaVu Sans"]
plt.rcParams["axes.unicode_minus"] = False   # 负号正常显示
plt.rcParams["savefig.dpi"] = 200            # 网页用图清晰度

# 读入清洗结果并按同一口径剔除异常薪资（清洗阶段只标记、不删除）
df = pd.read_csv("cleaned_jobs.csv", encoding="utf-8-sig")
df["月薪中点"] = pd.to_numeric(df["月薪中点"], errors="coerce")
df.loc[df["薪酬_异常"].fillna(False).astype(bool), "月薪中点"] = np.nan
df.loc[(df["月薪中点"] < 1000) | (df["月薪中点"] > 200000), "月薪中点"] = np.nan

# 脏值合并：转义符把同一个值拆成了两类（"在校生\\/应届生" vs "在校生/应届生"）
df["工作经验要求"] = df["工作经验要求"].astype(str).str.replace("\\/", "/", regex=False)

# 分组聚合：一次性拿到岗位数 + 薪资中位数
g = (df.groupby("学历要求")
       .agg(岗位数=("学历要求", "size"), 薪资中位数=("月薪中点", "median"))
       .reindex(["本科", "大专", "硕士", "博士", "中技/中专", "高中", "初中及以下"]))
```

**运行方式**

```bash
pip install pandas numpy matplotlib
# 仓库内已附带清洗后数据，可直接复现
python src/job_visualization.py data/clean_jobs_3498.csv charts
```

脚本会输出 4 张 PNG 到 `charts/`，并在控制台打印每张图背后的完整数字表，便于图表与结论逐项核对。

**环境说明**：Windows + Python 3.13 / 3.11（Anaconda），matplotlib 使用 `Agg` 非交互后端，无需图形界面即可出图。

## 五、口径与局限性

写清楚边界，结论才可信。以下五点会直接影响结论的适用范围：

1. **样本是主题垂直切片，不是全市场。** 原始数据为「大数据开发」主题检索结果，去重后仅 44 类职位名称、69 家公司，因此技能词频会被少数公司的模板化 JD 放大，不能外推为「全国大数据岗位技能需求」。
2. **快照时间较早。** 数据集中在 2022-11，与当前招聘市场存在时间差，趋势类结论（如某技能是否升温）不可用。
3. **薪资离散化严重。** 薪酬为区间报价换算，导致各分组中位数差异普遍小于一个报价档，图 1 的薪资对比只能说明「量级相当」，不能支撑精细的溢价测算。
4. **经验字段存在推断成分。** 原始数据中经验、学历各缺失 475 / 476 条（各占 11.6%），这些值由 `地区经验学历` 列回填；该列本身是页面上的结构化字符串，回填准确但口径依赖原站点。
5. **川渝子样本极小。** 成都 184 条、重庆 78 条，其中「大专 + 无需经验」仅 6 条，任何按城市 + 学历 + 经验三重交叉的结论都受样本量限制，只能作为方向参考而非统计结论。

> 上述局限性不影响「学历是门槛、经验权重更高、SQL 优先级最高」这三个方向性判断，因为它们在各细分切片中方向一致；但任何具体数值都不应脱离本数据集单独引用。
